# TradeScope V2 · 交易决策看板

一个**可部署的静态网页**，支持 iPhone / Windows 浏览器使用；连接 Supabase 后可跨设备同步。

## 当前已实现

- MU、NVDA、GOOGL 截图价格示例，显示时间及数据来源；添加股票并编辑成本价、股数、关键价位。
- 把分析粘贴到文本框，**选中文字**收藏、置顶；可以编辑、删除、按股票筛选。
- 自定义价格观察条件；主动更新报价时检查条件（**不提供后台通知或自动交易**）。
- JSON 导入、导出；未连接云端时使用浏览器 `localStorage`。
- Supabase 邮箱密码登录，Postgres JSONB 一行一账号保存，同账号跨设备下载/上传，自动保存已加载的云端工作区。
- 可选 Finnhub 手动报价：必须自备 API Key。当前版从前端请求，密钥会存储在本机浏览器，并可能在浏览器开发工具中暴露，**仅供个人试用，勿用高权限或付费密钥**。

## 本地试用

打开 `index.html` 即可试用。为避免移动 Safari 对 `file://` 本地存储的限制，推荐部署成 HTTPS 网页。

## 部署网页（Cloudflare Pages / Netlify / GitHub Pages 等）

将 `index.html`、`styles.css`、`app.js` 上传到**同一个静态站点根目录**。例如在 GitHub 建仓库后，将三文件提交，并通过 Settings → Pages 部署（仓库项目站点的 URL 即网页地址）。务必把 `schema.sql` 留在私有环境或本地；它不含密钥。

## 启用跨设备云端同步（Supabase）

1. 在 https://supabase.com 创建一个项目，并在 SQL Editor 执行 `schema.sql`。项目需启用 Email/Password Auth。
2. 在 Supabase 项目的 `Project Settings → API`（不同版本入口可能变化）找到 **Project URL** 与 **anon / publishable key**。**绝对不要**把 `service_role` 或 secret key 放进网页。
3. 打开网页“连接与设置”，输入 URL、anon/publishable key，点击“保存连接参数”；注册邮箱账号，若要求邮箱验证，先完成验证后登录。
4. **第一个设备**：登录后若提示云端无数据，切换“数据与备份”，点击“手动上传本机数据到云端”。
5. **第二个设备**：访问相同网页，填写相同 Supabase 项目 URL/key，使用相同邮箱登录，云端数据将下载到此设备。
6. 后续修改会自动上传（需浏览器联网且页面仍保持打开）。同步失败时仍会本地保存。建议编辑后确认顶部的“已同步”，并定期导出备份。

## 重要限制与安全事项

- 为了易于部署，数据是整份 JSON 覆盖同步，**两个设备不要同时编辑**；否则最后写入可能覆盖此前修改。本项目没有版本历史、冲突合并、端到端加密。
- 当前 Supabase access/refresh token 存储于浏览器 localStorage，适合私人原型，不宜存放交易凭证、银行卡号等敏感数据。生产版应强化认证、CSP、安全审计及会话管理。
- 重新打开页面后，已有本地登录缓存**不会在后台自动上传**；需重新登录以加载云端最新版本，避免把旧的本地数据覆盖云端。
- Finnhub 可能不支持某些标的或某些免费套餐的使用方式；以返回价格时间戳和供应商条款为准。图中原始 2026-10-15 价格只是用户截图示例，不能作为实时行情。
- 行情条件检测仅在主动更新时发生，不会后台扫描、发推送或下单。要实现后台监测，需另行部署受保护的服务器定时任务和通知通道。
- 交易所行情订阅、API 限额以及云端免费额度可能变化，以服务商当前条款为准。

## 代码文件

- `index.html`：网页结构与交互入口
- `styles.css`：桌面/手机自适应样式
- `app.js`：本地管理、云端认证同步、可选 Finnhub 报价
- `schema.sql`：Supabase 数据表及 Row Level Security 策略

此软件仅用于信息整理和投资研究，不连接交易所进行真实买卖。
